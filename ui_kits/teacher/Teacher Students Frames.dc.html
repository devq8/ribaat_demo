Teacher / assistant dashboard — Students List view + student detail view, both themes, desktop primary with one tablet frame.
Two live components matching the two Django templates: TeacherStudents.dc.html (list) and TeacherStudentDetail.dc.html (detail). Search, all three filters (course, track, country), all four sortable columns and pagination are interactive in place; clicking a row marks that student as the one open in the detail frame below. Navigation sits in the same top bar as the Overview — wordmark + «لوحة المعلم» badge and an inline scrollable nav (Students active, parked sections muted), with notifications and the account opposite; no breadcrumbs, the detail view keeps its back link.
1a Students list · Desktop · Light
1440px. Filter bar first (search by name/email, course, track/level, country, reset), then the result line with removable filter chips, then the table: student (avatar + email + a طالب/طالبة chip), age, country, enrolled courses with track, overall progress as a compact ProgressBar + percentage, last login (اليوم/أمس + time, else date). Five column headers sort — the arrow marks the active column and direction. The row of the student shown in the detail frame is tinted. Pagination sits inside the card, 8 rows per page.
1b Students list · Desktop · Dark — filtered
Same screen with a course filter applied, so the chip row and the filtered result count are visible. Warm dark tokens: parchment neutrals go dark-warm, the green stays the single accent.
1c Student detail · Desktop · Light
Read-mostly oversight: header (avatar, name, level badge, e-mail, enrolment date with its Hijri equivalent, last activity), four standing figures, then tracks and courses — both using the established title + Badge + labelled ProgressBar pattern from CourseCard — then exam results scored against each exam's own success threshold, then issued certificates with serial and «الاستعلام عن الشهادة». No fields are editable here; account data lives in المستخدمون.
1d Student detail · Desktop · Dark
Same detail view in dark mode. Pass/fail scores keep the muted semantic colors; the failed attempt reads «لم يجتز — إعادة متاحة» rather than a bare red badge.
1e Students list · Tablet · Light — 834px
The table reflows to one card per student rather than scrolling sideways: the four table columns become a name row, a meta row (courses, track, enrolment) and a full-width labelled progress bar — a teacher can still scan progress down the page. The sidebar collapses to an 84px icon rail; filters and pagination are unchanged.
1f Student detail · Tablet · Light — 834px
Detail view under the same top navbar; the exam table becomes stacked rows so score, threshold and result stay readable without horizontal scrolling.
1g Mobile fallback — 390px, list + empty result
Basic non-broken fallback: the top nav becomes a horizontally scrolling strip in the header (square mark, no badge), cards stack. Second frame shows the no-match state a search can produce.
