Authentication — Login, Signup, Forgot & Reset password One shared shell, four screens, three breakpoints, both themes.
Every frame below is the same live component — RibaatAuth.dc.html — driven by props (screen, signupPath, signupStep, viewport, colorScheme, demoState). The frames are interactive: type in the fields, submit to see per-field validation and the loading spinner, move through the signup stepper, follow «نسيت كلمة المرور؟» into the reset flow. For the React build, the prop split maps to components: AuthLayout (the shell) → LoginForm / SignupStepper / ForgotPasswordForm / ResetPasswordForm, with SignupStepper holding all step values in one client-side state object and rendering StepAccount, StepPersonal, StepContact, StepReview. Shared shell: at ≥1024px a split grid — olive brand panel on the right (RTL start) with mark, wordmark and one restrained line about the school, form column on the left, form itself capped at 420px so fields never stretch. Below 1024px the panel drops away and the mark + wordmark stack above the form in a single centered column (44px minimum tap targets throughout). Footer strip is the same on every screen: certificate lookup, support, school name. Error treatment: the offending field gets a --state-danger-fg hairline border and a --state-danger-bg fill, plus a small alert icon and one plain-language sentence directly under it — no top-of-form banner, no exclamation marks, nothing red beyond those two hairline-weight cues. Loading: the primary button keeps its size, swaps its label for a spinner and disables.
1a Login · Desktop · Light
1440×900. Social first as three stacked full-width rows — provider glyphs stay recognizable but the buttons themselves are Ribaat's own paper surface + hairline border, so nothing shouts; only Google keeps its four-color mark (it is unreadable in monochrome), Apple and Facebook are drawn in ink. Then the «أو» rule, then the email/username + password pair with the show/hide eye inside the field and «نسيت كلمة المرور؟» on the label row where the eye can't collide with it.
1b Login · Tablet · Light
834×1100 (portrait). Panel drops, mark + wordmark stack above the form, form widens only to 440px and stays centered. A landscape tablet ≥1024px gets the split layout of 1a instead.
1c Login · Mobile · Light
390×880. Same order, tighter padding (20px), heading drops one step to 28px. Buttons and fields are 46px tall.
1d Login · Desktop · Error — wrong credentials
A credentials failure is one fact, not two, so it is written once — under the password field, the last thing the student touched — while the field itself carries the tinted state. Wording states what happened and what to do, and never blames: «البريد الإلكتروني أو كلمة المرور غير صحيحة. تحقق من البيانات وحاول مرة أخرى.»
1e Login · Desktop · Submitting
The shared loading state: label out, spinner in, button disabled at 50% opacity and the same height, so nothing below it moves. Identical on every submit in the set (next step, send reset link, save password, final signup).
1f Signup · Step 1 of 4 · Desktop · Light
Step indicator is a title + counter row over four hairline segments — enough to show progress without a heavy numbered rail. Grouping now matches the confirmed backend field list: 1 بيانات الحساب (name, email, password1, password2) · 2 البيانات الشخصية (gender, date_of_birth, nationality) · 3 التواصل والإقامة (phone_country_code + phone on one row, country, city) · 4 المراجعة والإقرار. Eleven fields is well past what one screen holds calmly, which is what the stepper is for — three short screens of two to four fields each, then a review. Step 1 also carries the social buttons, since choosing a provider here replaces this step rather than adding to it. Password strength is a three-segment hairline, not a score. Counter uses Western digits («الخطوة 1 من 4») to match counts elsewhere in the product — say the word and it becomes ١ من ٤.
1g Signup · Step 1 · Tablet
834×1240. Nothing reflows except the shell — the stepper, fields and actions are the same column.
1h Signup · Step 1 · Mobile
390 wide, shown at full page height (1180) — on an 844-tall phone this is the one screen in the set that scrolls, which is the argument for the stepper: four short screens instead of one long one.
1i Signup · Step 1 · Two fields in error
Per-step validation runs on «التالي», never mid-typing; an error clears the moment that field is edited. Two fields fail here — a taken email and a mismatched confirmation — and both are marked independently, so the student can see at a glance that the name, password and everything else is fine. The taken-email message offers the exit: «يمكنك تسجيل الدخول بدلاً من ذلك».
1j Signup · Step 2 · Personal data
Back/Next appear from step 2 on; «السابق» is the outline variant so the primary action stays the only filled button. Open question for implementation: where the partial state lives — localStorage only (survives a refresh, not a device change, no server record of an incomplete person) or a server-side draft keyed by the verified email (survives everything, but stores personal data before the terms are accepted). Recommendation: localStorage for v1, expiring after 7 days.
1j2 Signup · Step 3 · Contact & residence
phone_country_code and phone are one combined control laid out LTR — country selector on the left, national number on the right — drawn to match react-international-phone's PhoneInput, which is what the React build should mount here (defaultCountry="kw", onChange giving the dial code and the national number, stored in the two backend fields). Its per-country mask is reproduced (Kuwait groups 4+4, Saudi/UAE 2+3+4), and the dial-code menu opens under the selector. Country flags sit in the selector and against every row of the menu, as the package renders them (drawn here from flagcdn.com; the package's own FlagImage sprite replaces them one-for-one in the build). They are the one image in the whole auth set — functional country identifiers, not decoration. city arrives pre-filled from GeoIP on web with the same «تم تحديدها تلقائيًا» note used for provider-supplied fields, and stays fully editable; on mobile it renders empty with no note (geoCity=false). nationality sits in step 2 with the personal data and uses nationality wording («كويتي»), while country here uses country wording («الكويت») — same underlying list, different labels, so the two are never confused on the review card.
1k Signup · Step 4 · Review & acknowledgment
Read-only summary in three cards mirroring the three data steps, each with «تعديل» jumping back to that step with everything preserved. The password is never echoed. Terms acknowledgment sits last, directly above «تسجيل»; leaving it unchecked marks the box itself and writes the reason beneath it — same treatment as any other field.
1k2 Signup · Confirmation after «تسجيل» · Desktop · Light
The terminal state of the signup flow: stepper, form and social block all drop out, so nothing suggests there is anything left to fill in. The order is deliberate — success mark, then the address the message went to (with «تغيير البريد» back to step 1 in case of a typo), then the one thing the user must understand: the account is not active yet. That notice uses the warning tint rather than success, because it is a pending condition, not a completed one. «ما تبقّى من الخطوات» spells out the three remaining actions. Primary action is «تسجيل الدخول» (available, but will bounce until confirmed), with resend as the outline secondary on a 60-second cooldown so the button can't be hammered.
1k3 Signup · Confirmation · Mobile
390 wide. Same single column, no reflow — the cards stack in the same order and the two actions stay full width, stacked primary over secondary.
1k4 Signup · Confirmation · Dark
In dark the success mark and the warning notice keep their hue but sit on the dark state tints, so the pending notice still reads as the loudest element on the page.
1l Signup · Social path · Step 1 «تأكيد بياناتك» · Desktop
Choosing a provider replaces step 1 rather than skipping it, so the counter still reads «الخطوة 1 من 4» and never jumps. A confirmation chip states that identity was verified and no password is needed; name and email arrive filled with «تم الحصول عليه من Google» under each — and stay editable, because providers routinely hand over a nickname, and this name is printed on the certificate. Steps 2–4 are identical to the email path; the review card notes Google as the sign-in method instead of a password row.
1m Signup · Social path · Step 1 · Mobile
390×880 — the social path is two fields shorter than the email path, so it fits a phone screen without scrolling.
1n Forgot password · Desktop
One field, one sentence of explanation in the subheading rather than a separate paragraph, one button. «تذكرت كلمة المرور؟ العودة إلى تسجيل الدخول» closes the loop.
1o Forgot password · Tablet · Unknown email
834×900, showing the field-level error: «لا يوجد حساب مسجل بهذا البريد الإلكتروني.» — worth deciding with the backend whether to disclose this at all, or always show the sent confirmation to avoid confirming which addresses exist. Both states are built.
1p Forgot password · Mobile

1q Forgot password · Sent confirmation
Same URL, same shell — the form is replaced in place by the confirmation card, so the address they typed stays on screen and the browser back button still means "back to login". States the 60-minute validity and where to look if nothing arrives; «إعادة إرسال الرابط» is the outline variant, since the student's real next action is in their inbox, not here.
1r Reset password · Desktop
Reached from the emailed link with the token already validated server-side. The subheading names the account being changed so the student can tell they opened the right link. New password carries the strength hairline and the requirement as a hint before it is ever an error.
1s Reset password · Tablet · Mismatch
834×900. Only the confirmation field is marked — the first password is not wrong, it just wasn't repeated correctly, and marking both would send the student back to re-type something that was fine.
1t Reset password · Mobile
390×820.
1u Reset password · Expired token
Not an error state on a field but a replaced form, in warning amber rather than danger red — nothing went wrong, time simply passed. It explains the 60-minute rule so the expiry makes sense, and «طلب رابط جديد» goes straight back to Forgot password with the flow intact.
1v Login · Desktop · Dark
The same warm dark tokens the dashboard uses — parchment neutrals go dark-warm, olive stays the single accent, nothing near black. Provider glyphs invert with the text except Google's, which is fixed by its brand rules.
1w Signup · Review · Dark
Review cards and the acknowledgment in dark: cards lift off the page on --surface-card with the same hairline, and «تعديل» links use the lighter dark-mode link token.
1x Reset password · Mobile · Dark · Error
The error treatment checked in the hardest combination: phone width, dark surface. The danger fill is a desaturated warm maroon, not a glow, and the message still clears the 4.5:1 bar against it.
